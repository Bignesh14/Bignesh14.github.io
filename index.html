Glimmer-M5-SelfTune

Can an AI model make its own inference faster, safely? I made Meta's Muse Glimmer 30B (4-bit) run faster on an Apple M5 Max, then built a referee that refuses any speed-up it can't verify.

0faster at best (median 12.8% over 19 prompts)
0paired runs faster, interleaved A/B races
0on a Spec-Bench subset (60 prompts, 6 tasks)
0"fast but wrong" model patches caught

What I built

  1. Prompt-lookup decoding with exact rollback. The model checks several guessed tokens per pass. I wrote exact KV-cache rollback for sliding-window attention, a case mlx-lm's own speculative decoder refuses past the window.
  2. Found a kernel cliff. MLX's fused attention kernel stopped being used for multi-token passes under grouped-query attention. Splitting attention into 2-query chunks cut a 3-token pass at 13.8K context from 1.44× to 1.21× the cost of one token.
  3. The referee. A bit-exact check against normal decoding (which traced one mismatch to MLX's default TF32), a safety gate, and replicated interleaved races. Nothing ships unless it wins all three.
  4. Anyone can try it. One command, a local web UI with an animated mascot, and it runs on 8 GB Macs with Llama 3.2 3B.

The twist

I asked Glimmer to write the attention fix itself. Across 16 attempts, none were correct. Ten were fast but wrong; the ones I traced quietly let the model look at future tokens.

A speed-only reward would have accepted all ten. The referee rejected every one.
